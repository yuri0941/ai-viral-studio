# OMEGA v5 — Полная Автономность (Autonomy Blueprint)
## AI Viral Studio | Архитектурный документ

---

## 1. Философия автономности

OMEGA работает по принципу **"Human-in-the-Loop"** с постепенным переходом к **"Human-on-the-Loop"**:
- **Сейчас (P2–P4):** OMEGA советует, вы решаете и жмёте кнопку.
- **P12 (OMEGA v5):** OMEGA сама выполняет рутину, вы только одобряете критические решения.
- **P13+:** OMEGA сама предлагает стратегические изменения, вы жмёте "✅ Одобрить" или "⛔ Отклонить".

---

## 2. Уровни автономности (5 ступеней)

| Уровень | Название | Что делает OMEGA | Ваше участие |
|---------|----------|------------------|--------------|
| **1** | Ассистент | Отвечает на вопросы, генерирует контент | Полное управление |
| **2** | Оператор | Мониторит метрики, шлёт алерты, сортирует задачи | Реагируете на алерты |
| **3** | Менеджер | Сама назначает задачи сотрудникам, публикует посты по расписанию | Одобряете план на неделю |
| **4** | Директор | Меняет цены, переключает сервера, нанимает фрилансеров | Одобряете бюджетные решения |
| **5** | Автоном | Запускает новые проекты, интегрирует новые AI, ведёт переговоры | Только Emergency Stop |

**Текущий статус:** Уровень 1–2 (P2–P4).  
**Цель P12:** Уровень 3–4.  
**Цель P13:** Уровень 5 (с ограничениями).

## 3. Модули автономности

### 3.1 OmegaAutoPilot (ядро)
Файл: `frontend/src/ai/omega/omegaAutoPilot.js`

```js
// Цикл автономности (каждые 60 секунд)
const AUTONOMY_CYCLE = {
  observe:    () => collectMetrics(),      // Собрать метрики
  orient:     () => analyzeContext(),       // Проанализировать контекст
  decide:     () => makeDecision(),         // Принять решение
  act:        () => executeAction(),        // Выполнить действие
  learn:      () => updateMemory(),         // Записать в память
  report:     () => notifyOwner(),          // Сообщить владельцу
}
```

**Правило:** Любое действие уровня 4+ требует `ownerApproval: true` по умолчанию.  
Настройка: `Settings → OMEGA → Автономность → Уровень`.

### 3.2 Self-Healing (самовосстановление)
- **Мониторинг:** Если API Groq падает → автопереключение на OpenRouter.
- **База данных:** Если MongoDB недоступна → fallback на localStorage + алерт.
- **Сервер:** Если CPU > 90% → масштабирование (запрос на Render/Vercel API).
- **Баги:** Если frontend падает (красный экран) → OMEGA предлагает hotfix, вы жмёте "Применить".

### 3.3 Self-Improvement (самосовершенствование)
- **Анализ кода:** OMEGA сканирует свои собственные файлы раз в сутки.
- **Рефакторинг:** Предлагает оптимизации (мемоизация, lazy loading).
- **Новые навыки:** Если появляется новый API (например, новая соцсеть) → OMEGA сама пишет интеграцию и просит одобрить.
- **Обучение на данных:** Чем больше данных о вашем бизнесе — тем точнее прогнозы.

### 3.4 Predictive Assistance (предиктивная помощь)
- **Утренний брифинг (9:00):** "Сегодня 3 задачи, 1 просрочена, рекомендую переназначить на Ивана."
- **Прогноз доходов:** На основе истории + сезонность + тренды.
- **Предупреждение оттока:** "Клиент X не заходил 7 дней — предлагаю email с персональной скидкой."
- **Рекомендация инвестиций:** "Свободно $5,000 — рекомендую купить токены Y (прогноз +12%)."

### 3.5 Business Spawning (рождение бизнеса)
- OMEGA анализирует тренды → находит нишу → генерирует MVP → деплоит за 48 часов.
- Вы получаете: "Нашёл нишу. Готовый лендинг + бот. Стоимость запуска: $47. Запустить?"

## 4. Границы безопасности (жёсткие правила)

### 4.1 Что OMEGA НЕ может делать без одобрения
- ❌ Снять деньги с вашего счёта (кроме фиксированных подписок).
- ❌ Удалить сотрудника или клиента.
- ❌ Изменить пароль/доступ Owner.
- ❌ Отправить сообщение от вашего имени в личных соцсетях.
- ❌ Заключить юридически значимый договор.
- ❌ Отключить Emergency Stop.

### 4.2 Emergency Stop (красная кнопка)
- Виджет в правом верхнем углу (всегда виден).
- При нажатии: OMEGA останавливает ВСЕ автономные процессы.
- Режим "Только чтение" — данные собираются, но действия не выполняются.
- Требуется ваш PIN-код для возобновления.

### 4.3 Лог всех автономных действий
- Каждое действие OMEGA записывается в `AuditLog` с меткой `autonomous: true`.
- Вы можете открыть `Аудит → Фильтр "OMEGA Auto"` и откатить любое действие.

## 8. Технические требования

- **Cron:** `node-cron` для фоновых задач (backend).
- **WebSocket:** Постоянное соединение для real-time алертов.
- **Queue:** `bull` или `bee-queue` для фоновых задач (email, генерация).
- **ML:** Простые модели на базе исторических данных (не требует GPU).
- **Sandbox:** Новые AI-интеграции тестируются в изолированном окружении.
